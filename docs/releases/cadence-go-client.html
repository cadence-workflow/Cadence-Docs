Release v1.4.0 published by shijiesheng on 9/28/2026​

Highlights

Workflow Schedules

Workflow Schedules is a durable server-managed scheduling primitive that replaces hand-rolled cron workflows. It supports overlap policies (Skip, Buffer, Concurrent, Cancel/Terminate Previous), catch-up on missed fires, jitter, backfill, and pause-on-failure.

What can the user do with it?

Cadence Schedules let you run a workflow on a cron-based schedule without managing the timer yourself. You can pause and resume a schedule without deleting it, trigger past runs on demand via backfill, control what happens when a previous run is still executing when the next fire is due (overlap policies), and configure whether missed runs should catch up or be skipped when a schedule is unpaused.

Why should the user use it?

Before Schedules, recurring workflows required either a Cadence Cron (using ContinueAsNew in a loop) or an external scheduler. Schedules move that complexity into Cadence: the server owns the timer, handles missed fires, and gives you lifecycle controls (pause, backfill, delete) through APIs, SDKs, and the CLI without touching workflow code.

What customers are using it? What is their use case?

Machine learning platforms like Michelangelo use Schedules to trigger training and scoring workflows on a recurring basis. Their primary requirement was the ability to pause a schedule during a lockdown or bug fix period without permanently deleting it, and to control whether missed runs should catch up or be skipped on resume.

Who can use it?

Any team running workflows on Cadence. Accessible via Go SDK, Python SDK, and the Cadence CLI.

Requirements

Cadence Server >= v1.4.1

Release v1.3.1 published by shijiesheng on 8/28/2026​

Highlights

Workflow / activity APIs

#1495 GetActivityOptions — hooks/middleware can read current options instead of only overwriting them. #1467 ResettableTimer — Reset() instead of cancel / handle CanceledError / start a new timer; replay-safe. #1459 NewBatchFuture left experimental x for stable workflow (import break for x users). #1447 HasActivityInfo — check activity context without panic/recover around GetInfo. #1479 Maybe() on mocks — optional / fire-and-forget assertions. #1451 Attempt number on activity (and local activity) logs.

Active-active / domains

#1438 ActiveClusterSelectionPolicy on start options (nil-safe; server first). Also filled in missed CronOverlapPolicy mapping. #1442 / #1446 Domain mappers for ActiveClusters / ActiveClustersByRegion. #1461 / #1478 FailoverDomain — failover as a write-permission API, not admin UpdateDomain. #1468 ListFailoverHistory and redesigned active-active IDL (breaks earlier RCs only). #1469 / #1470 Public ActiveClusterSelectionPolicy and ClusterAttribute types.

Client / query

#1445 / #1456 …WithOptions + QueryConsistencyLevel; STRONG reads the active cluster (higher latency on passive). Old methods unchanged. #1490 Auto-forwarding flag — workers on a passive cluster can still poll/process when the server forwards. #1486 cadence-caller-type: sdk so frontend can tell SDK vs other clients. #1458 Request IDs on APIs that lacked them — idempotent retries, especially signals.

Workers / sessions / metrics

#1449 Ephemeral session task lists (flagged); per-host lists go away when unused. Needs server TaskListKind or polls error. #1460 Helpers/docs for experimental blocks Query UI. #1489 Dual-emit timers as histograms (more series until migration ends). #1437 Task-permit gauges → histograms for a real distribution.
